# 小程序功能与需求基线

更新时间：2026-09-14

本文档根据 `/Volumes/macOS/owner/bookkeeping` 当前小程序代码和
`/Volumes/macOS/owner/node-fatboy` 当前记账前端接口整理。它描述代码已经证明的能力，
并把后续方向标记为建议，不能替代真机、线上接口和生产数据验证。

## 一、产品范围

当前产品是个人收支记账小程序，核心闭环是：微信进入、记录一笔、查看近期流水、
按日/月/年查看收支、编辑或删除流水、设置月预算、查看统计和个人资料。

当前范围不包含企业对账、银行流水导入、多账户余额、家庭成员协作或自动化记账。
这些能力可以规划，但需要新的业务模型和接口约定。

## 三、当前接口闭环

小程序当前调用的记账前端接口包括：

- 身份：`/frontend/bookkeeping/auth/openid`、`/auth/user-info`、`/auth/avatar-upload`
- 分类：`/frontend/bookkeeping/category/list`、`create`、`delete`
- 流水：`/transaction/recent`、`create`、`update`、`delete`
- 汇总：`/transaction/month-bill`、`year-bill`、`month-bill/detail`
- 分析：`/transaction/calendar`、`expense-trend`、`category-distribution`
- 预算：`/budget/detail`、`save`、`item`、`reset`
- 成就：`/achievement/list`
- 反馈：`/feedback/upload`、`/feedback/create`

请求通过 `ensureOpenId()` 获取或复用微信 `openId`。当前小程序请求主要使用
`skipToken`，所以接口安全边界不能按传统用户 token 会话理解。

## 四、已实现但需要补强的部分

### 1. 自定义分类

“我的”页面提供分类管理入口。默认分类对所有用户可见且不可删除；自定义分类写入创建者
`openId`，查询时只返回默认分类和当前用户自己的自定义分类。删除采用停用方式，历史流水
仍保留分类引用，用户之后可以重新创建同名分类。

### 2. 头像已具备上传链路，但需要线上验证

选择头像后，小程序调用 `auth/avatar-upload`，拿到七牛云地址，再调用 `auth/user-info`
保存。需要在开发、体验和正式环境分别验证七牛域名、图片访问权限、失败重试和旧头像
清理策略。

### 3. 会员中心目前是展示层

会员权益和价格页面已经存在，但当前小程序代码没有看到支付下单、支付回调、订单状态
查询或权益校验闭环。不能把页面展示当作会员购买已实现。

### 4. 删除流水是直接删除

首页和详情可以删除流水，后台 `delete` 直接执行删除操作。建议改为软删除或增加回收站、
审计记录和恢复能力，并统一处理统计缓存刷新。

## 五、可以直接进入开发的需求

这些需求与当前架构匹配，主要是补齐接口和页面状态：

| 优先级 | 需求 | 需要增加的内容 | 验收结果 |
| --- | --- | --- | --- |
| P0 | 自定义分类持久化 | 分类表字段、用户分类接口、前端分类管理 | 新增分类重新进入小程序仍存在，流水和统计可正确关联 |
| P0 | 流水幂等提交 | 客户端请求 ID、后端唯一约束或幂等表 | 重复点击保存不会生成两笔相同流水 |
| P0 | 数据导出 | 后端按用户导出 CSV/JSON，前端下载或生成文件 | 用户可导出指定时间范围的完整流水和分类 |
| P0 | 账户数据删除 | 删除确认、用户资料/流水/预算/反馈关联数据策略 | 用户能发起删除并得到明确结果 |
| P1 | 流水搜索和筛选 | 标题/备注/分类/金额/日期查询参数，前端筛选页 | 能按关键字、分类和日期找到流水 |
| P1 | 预算提醒 | 预算阈值配置、服务端计算、订阅消息或站内提示 | 达到 80%/100% 时产生可追踪提醒 |
| P1 | 周期记账 | 周期规则、到期生成、重复防护、暂停/恢复 | 可管理固定房租、工资等周期流水 |
| P1 | 流水附件 | 七牛图片上传、附件关联表、详情查看/删除 | 流水可保存并查看凭证图片 |
| P1 | 统计导出和分享 | 统计快照、图片/文件导出、分享参数脱敏 | 分享内容不暴露 openId 和隐私字段 |

## 六、需要产品先定规则的需求

### 多账户和期初余额

需要确定账户类型、账户余额、转账规则、期初余额、跨账户流水和结余口径。当前的
`totalBalance` 是收支统计结果，不能直接扩展成钱包余额。

### 家庭成员协作

需要确定家庭、成员角色、邀请、数据范围、共同账户和退出家庭后的数据归属。当前
数据按 `openId` 查询，不能直接开放给其他用户。

### 对账和账单导入

需要确定文件格式、字段映射、去重规则、自动匹配、差异处理、确认历史和隐私策略。
这是一套独立的对账流程，不应仅在现有账单列表上增加导入按钮。

### 自动记账和通知监听

微信小程序无法直接监听手机上的微信/支付宝支付通知。若要实现，需要 Android/iOS
原生能力、权限说明、待确认记录和隐私合规设计。

### 会员支付

需要确定商品、价格、微信支付商户配置、订单状态机、退款、权益有效期和服务端校验。
在这些条件明确前，只能继续完善会员介绍页。

## 七、建议开发顺序

1. 先做 P0 数据可靠性：幂等、真实分类、软删除/恢复、导出和账户删除。
2. 再做 P1 高频效率：搜索筛选、周期记账、预算提醒、附件。
3. 最后根据产品定位选择多账户、家庭协作、导入对账或会员支付。

每个需求都应同时补充接口契约、异常状态、权限边界、空状态、失败重试和真机验收，
避免只完成页面而留下不可用的后端链路。

## 八、验证边界

- 当前源码和本地路由可以证明页面结构、请求路径和前端状态处理。
- `npm run typecheck` 可以证明小程序 TypeScript 类型检查通过。
- 微信开发者工具预览可以证明当前项目可编译打包。
- 真实接口数据、七牛云访问、微信分享、支付、通知权限和不同设备布局仍需在目标
  环境验证。
