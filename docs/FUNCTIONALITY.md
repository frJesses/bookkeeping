# 钱小迹功能说明与优化路线图

> 文档版本：1.0  
> 盘点日期：2026-09-04  
> 对应应用版本：1.0.2  
> 盘点依据：`bookkeeping` 小程序与 `node-fatboy` 记账接口的当前工作区源码，包含尚未提交的本地改动。本文档说明的是源码实现状态，不代表体验版、正式版或线上接口已经逐项验收。

## 1. 产品定位

钱小迹当前是一款个人收支记账与数据分析微信小程序，核心闭环是：

1. 获取微信用户标识。
2. 记录一笔收入或支出。
3. 在首页、账单和统计页查看汇总与趋势。
4. 查看、编辑或删除已有记录。

当前产品更准确的定位是“个人记账”，还不是严格意义上的“个人对账”。账单文件导入、自动匹配、差异处理和对账确认均未实现，不能在宣传文案中描述为已具备对账能力。

## 2. 状态定义

| 状态 | 含义 |

## 4. 当前功能详细说明

### 4.1 用户身份

- 小程序启动时调用 `wx.login` 获取临时 code。
- 后端使用 code 换取微信 `openId` 和可选的 `unionId`。
- `openId` 会写入全局数据和本地缓存，避免每个页面重复登录。
- 新 `openId` 首次访问时，后端自动创建对应的记账用户。
- “我的”页面根据 `openId` 查询用户资料和记账汇总。

异常规则：

- 获取不到 code、微信配置缺失或换取身份失败时，请求会报错。
- 当前业务接口普遍由客户端直接传 `openId`，不能视为可靠的用户授权证明。

### 4.2 首页

- 默认展示当月数据，可在最近 12 个月中切换。
- 汇总区展示本月收入、本月支出和本月结余。
- 支持隐藏或显示首页金额。
- 最近记录按发生日期分组，组内展示当日收入、支出及每笔记录。
- 列表按发生时间倒序分页加载，每页默认 10 条。
- 点击记录进入详情；空状态可直接进入支出记账。
- 首页可分别从快捷入口进入收入或支出记账。

### 4.3 新增与编辑记录

- 支持收入、支出两种记录类型。
- 分类来自后端启用分类列表，并按收支类型切换。
- 必填项为分类和大于 0 的金额。
- 支持整数、小数、退格、加法和减法；表达式需要先计算，再完成保存。
- 支持填写备注和选择发生日期，不能选择未来日期。
- 新增时保留当前时分秒；编辑仅修改日期时保留原记录时分秒。
- 编辑成功后返回原列表，删除前弹出确认框。

### 4.4 账单与月度详情

- 账单页支持最近 8 个年份。
- “月账单”按月份展示收入、支出和结余，可进入月度详情。
- “年账单”展示所选年份的全年汇总。
- 当前年份只返回 1 月至当前月，历史年份返回完整 12 个月，未来年份为空。
- 月度详情展示本月结余、上月结余、收入和支出。
- 支出分类展示金额和占比；分类较多时将第 6 名以后合并为“其他”。
- 页面展示支出前三名，并可进入完整支出排行。
- 支出趋势包含单日最高、日均、本月总额和每日折线图。
- 近 6 个月支出通过柱形对比展示。

### 4.5 收支报表

- 时间粒度：最近 52 周、最近 24 个月、最近 10 年。
- 数据方向：支出和收入。
- 汇总指标：本周期总额、日均或月均、相对上一周期的金额差、上一周期同类型金额。
- 折线图展示所选周期内的每日或每月变化。
- 柱形趋势展示历史周期对比，并支持点击查看柱体标签。
- 数据接口支持周、月、年以及指定日期查询。

### 4.6 我的、分享与关于

- 展示昵称、头像、连续记账天数、累计记账天数和累计记账笔数。
- 支持通过微信分享卡片推荐钱小迹。
- 关于页展示应用名称、版本、口号和当前产品亮点。

## 5. 部分完成和已知问题

| 优先级 | 项目 | 当前情况 | 完成标准 |
| --- | --- | --- | --- |
| P0 | 业务鉴权 | 接口信任客户端传入的 `openId`；更新、删除仅按记录 ID 操作 | 后端从可信会话获取用户身份，所有查询和写操作校验数据归属 |
| P0 | 记录详情 | 详情数据来自上一页写入的本地缓存 | 新增前台详情接口，通过 `id + 当前用户` 获取记录；刷新和分享进入均可恢复 |
| P0 | 写入可靠性 | 新增记录没有幂等约束，连续点击或网络重试可能重复记账 | 客户端生成幂等键，后端保证同一请求只创建一次，保存期间禁用重复提交 |
| P0 | 统计指标 | “收支结余”实际使用上一周期同类型金额 | 改名为“上期支出/上期收入”，或由后端返回真实收入减支出的结余 |
| P0 | 预算 | 页面可输入并提示保存成功，但读写服务为空 | 有明确入口、真实读写接口、年度/月度预算回显、校验、进度和超支提醒 |
| P0 | 错误反馈 | 首页和“我的”在请求失败时可能直接显示 0 或空数据 | 网络失败、无数据和真实 0 三种状态可区分，并提供重试 |
| P1 | 年度账单封面 | 显示“点击开启”但没有交互 | 绑定完整年度报告动作，或删除误导性的按钮文案 |
| P1 | 账单金额隐藏 | 代码中有切换方法，但页面没有操作入口 | 增加眼睛图标入口并与首页的隐藏状态保持一致，或移除无效逻辑 |
| P1 | 预算入口 | 页面仅注册在路由中，现有导航没有入口 | 在“我的”或首页提供清晰入口，并确保返回路径正确 |
| P1 | 金额精度 | 前端计算主要使用 JavaScript `number` | 金额统一使用整数分或十进制定点方案，接口、汇总和展示规则一致 |
| P1 | 数据管理 | 没有导出、注销、数据删除、备份和恢复 | 用户可导出自己的数据，可发起可确认的数据清除，并有隐私说明 |
| P1 | 自动化验证 | 只有 TypeScript 类型检查脚本 | 覆盖金额计算、日期边界、汇总映射、重复提交和关键页面流程 |

## 6. 尚未实现的个人对账能力

若产品目标确实是“个人对账”，建议在现有记账闭环稳定后增加以下流程：

1. 账户与期初余额：现金、银行卡、微信、支付宝等账户，支持期初余额和账户间转账。
2. 账单导入：由用户主动选择微信、支付宝或银行导出的 CSV/Excel 文件，不模拟登录、不抓取支付账户。
3. 导入预览：识别字段、展示异常行、允许用户确认账户、时间范围和金额方向。
4. 重复检测：通过来源、交易单号、账户、时间、金额等字段避免重复导入。
5. 自动匹配：按金额、日期、收支方向、账户、商户或交易单号匹配已有记录。
6. 差异工作台：分为已匹配、待确认、仅账本存在、仅账单存在、已忽略。
7. 手工处理：允许关联、拆分、合并、取消匹配、补记和忽略，并保留操作记录。
8. 对账结果：展示期初余额、收入、支出、转账调整、期末余额和未处理差异。

建议采用以下余额口径：

```text
期初余额 + 收入 - 支出 + 转账调整 = 期末余额
```

## 7. 功能完善路线图

### 7.1 P0：形成可正式使用的记账闭环

- 完成可信登录态、数据归属校验和接口权限控制。
- 将详情页改为按 ID 加载真实数据。
- 为新增、编辑和删除补齐提交中状态、幂等和失败恢复。
- 修正统计指标语义和月度“结余率”计算口径。
- 预算若暂不开发，应隐藏页面入口和关于页宣传；若保留，则一次完成持久化、回显和提醒闭环。
- 统一网络失败、空数据、真实 0 和加载状态。
- 增加金额、日期、汇总与关键增删改流程测试。

### 7.2 P1：补齐个人财务管理能力

- 账单搜索与筛选：关键词、分类、收支类型、金额区间和日期范围。
- 自定义分类、常用分类排序和最近使用分类。
- 月预算、分类预算、预算进度和临界/超支提醒。
- 多账户、期初余额和账户间转账。
- 周期记账和到期提醒。
- 数据导出、数据清除、隐私说明和恢复方案。

### 7.3 P2：建立个人对账闭环

- 完成账单文件导入、解析预览和重复检测。
- 完成自动匹配、手工差异处理和对账结果确认。
- 支持按账户和月份查看对账历史，保留规则、来源和操作记录。
- 在对账稳定后，再考虑 OCR、家庭共享、AA 结算、多币种和异常消费提醒。

## 8. UI 优化建议

### 8.1 全局设计规则

| 项目 | 建议 | 验收标准 |
| --- | --- | --- |
| 色彩 | 固定主色为 `#4e62ff`，收入用绿色，支出用红色或暖色；分类色只用于图标和图表 | 同一含义在所有页面使用同一颜色，不仅依赖颜色表达状态 |
| 圆角 | 页面工具区和内容卡片控制在 16-24rpx，胶囊只用于切换、日期和小标签 | 不再同时出现 16、24、30、34、44rpx 等大量近似规格 |
| 阴影 | 普通内容以边框或轻阴影为主，主汇总区才使用明显阴影 | 列表滚动时层级稳定，不出现所有模块都悬浮的感觉 |
| 字体 | 建立页面标题、金额、模块标题、正文、辅助文字 5 级字号 | 长金额、长备注、长昵称在窄屏不重叠、不撑开布局 |
| 金额 | 统一货币符号、正负号、千分位和两位小数规则 | 不再混用 `¥ 0.00`、`¥0.00`、`-3` 等格式 |
| 状态 | 统一骨架屏、加载、空数据、失败、提交中和禁用样式 | 用户能一眼区分“没数据”和“加载失败” |
| 导航 | 自定义标题栏统一返回图标、标题位置和胶囊避让 | 320-430px 宽度及异形屏下无标题偏移或点击遮挡 |

### 8.2 分页面建议

#### 首页

- 保留“月结余 + 收入 + 支出”作为第一视觉层级，弱化背景装饰，确保金额对比度。
- 金额隐藏状态应跨首页、账单和统计页保持一致，不要每页单独重置。
- 最近记录增加明确的加载失败提示；真实空数据才显示“去记一笔”。
- 预算完成后，可在汇总卡下增加一条紧凑预算进度，不再新增大型卡片。

#### 记一笔

- 将“最近使用分类”放在分类区第一行，减少高频记账点击次数。
- 选中分类后保持金额面板稳定，软键盘、日期选择器和底部安全区不能互相遮挡。
- 保存期间禁用完成按钮并显示提交中，失败后保留用户已输入的金额、分类和备注。
- 编辑已有记录时，标题明确显示“编辑支出”或“编辑收入”，离开前提示未保存修改。

#### 账单与月度详情

- 年份选择、月/年切换和金额隐藏应形成一行清晰工具栏。
- 历史年度封面要么真正可进入年度报告，要么移除“点击开启”，避免伪按钮。
- 月度详情的信息顺序建议固定为：收支结余、分类去向、趋势、排行、历史对比。
- 月度详情当前采用绿色背景照片和彩色图表，和全局蓝色主视觉差异较大；建议保留白底、主蓝和收支语义色，图片只作为低对比度局部素材。
- 分类圆环、每日折线和月度对比保留两种核心图表即可，避免同页图表过多导致阅读负担。

#### 统计

- 先修正指标名称和数据含义，再继续视觉优化。
- 顶部已经使用紧凑日期胶囊与收支胶囊，后续保持此模式，不再改回大块筛选卡。
- 折线图负责当前周期变化；第二张图优先改成分类占比或同比贡献，避免两个趋势图表达重复。
- 图表无数据时显示说明和记账入口，不渲染空坐标系。
- 柱体和折线点击区域至少 44px，并提供明确的金额、日期提示。

#### 我的与关于

- “我的”目前只有分享和关于，内容偏空；优先补充预算、分类管理、数据导出、隐私与数据清除等真实入口。
- 用户统计区压缩顶部高度，让常用设置在首屏可见。
- 关于页应删除尚未完成的“预算管理”宣传，或等预算闭环后再恢复。
- 关于页装饰较多，建议把视觉重点放在品牌、版本、隐私政策和联系反馈，减少与工具型产品无关的装饰层。

### 8.3 UI 验收清单

- 微信开发者工具至少检查 320px、375px、430px 三档宽度。
- iOS 和 Android 真机检查顶部胶囊、底部安全区、自定义导航和弹窗层级。
- 验证 0 元、负结余、7 位金额、长分类、长备注、长昵称和无头像。
- 验证加载中、无数据、接口超时、业务错误、重复点击保存和返回重进。
- 验证折线图、柱形图、日期选择弹层及底部导航没有遮挡或误触。
- 对首页、记账、账单、月度详情、统计和“我的”各保存一张基准截图，后续 UI 修改做前后对比。

## 9. 建议的下一版本验收目标

下一版本不建议同时铺开大量新功能，先完成以下 6 项即可形成更可信的版本：

1. 用户只能读取和修改自己的记录。
2. 详情页可通过记录 ID 独立打开和刷新。
3. 新增记录不会因重复点击产生两笔数据。
4. 统计指标名称与真实数据完全一致。
5. 预算要么真实可用并有入口，要么不再展示和宣传。
6. 所有核心页面都能区分加载失败、无数据和真实 0。
